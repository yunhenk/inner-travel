## 2. 分层与依赖方向

```text
content/meridians/*.json
        │ import（构建期）
        ▼
apps/web ──────► @inner/core ──────► zod
   │                 ▲
   ├──────────► @inner/scene-gen ───┘
   │
   └──────────► @inner/render ──────► three
```

| 层 | 允许依赖 | 禁止 |
| --- | --- | --- |
| `packages/core` | `zod`、纯 TS | three、DOM、Node fs |
| `packages/scene-gen` | `@inner/core` | three、DOM |
| `packages/render` | three、`@inner/core`、`@inner/scene-gen` | 业务状态、内容解析 |
| `apps/web` | 上述全部、React、three | 地形/曲线算法（应下沉） |

规则的理由：

1. **可单测**：core 与 scene-gen 都能在 Node 里跑，`pnpm test` 不需要浏览器。
2. **可搬进 Worker**：scene-gen 的输出全是 TypedArray 与普通对象，`protocol.ts` 已按 transferable 设计。
3. **可替换渲染**：未来换 WebGPU 或换 2.5D 画卷，只动 render/web，地形算法不动。

> 路径别名 `@inner/*` 同时配置在 `tsconfig.base.json`（类型检查）与 `vitest.config.ts`（测试），Vite 通过 workspace 包解析 `exports: ./src/index.ts` 直接读源码。

## 4. `packages/core` —— 领域层

```text
core/src/
├─ schema/meridian.ts     # zod schema、类型、parseMeridian/findPoint
├─ math/vec3.ts           # 不可变 Vec3 元组与向量函数
├─ anatomy/hand.ts        # 世界约定、骨骼帧、手背高度场、手指/前臂、锚点距离
├─ meridian/curve.ts      # 向心 Catmull-Rom + 弧长重采样
├─ meridian/route.ts      # 穴位 → 世界坐标 → Route（stop.s / nearestStop）
├─ meridian/wushu.ts      # 五输阶段 → 河宽/流速/下切参数与插值
├─ time/tide.ts           # 十二经当令与潮位曲线
├─ rng/mulberry32.ts      # 确定性随机与字符串哈希
└─ index.ts               # 统一导出
```

### 关键文件

| 文件 | 关键导出 | 说明 |
| --- | --- | --- |
| `schema/meridian.ts` | `MeridianSchema`、`parseMeridian`、`findPoint`、`Meridian`、`Acupoint` | 运行时校验；重复编码、经脉 id 不一致会抛错 |
| `anatomy/hand.ts` | `palmDorsalY`、`palmDorsalNormal`、`FINGERS`、`distanceToHandBody`、`frameToWorld`、`FRAMES` | M0 的程序化体表；GLB 替换时只改「表面查询」接口 |
| `meridian/curve.ts` | `MeridianCurve`、`CurveFrame` | `controlS` 给出每个穴位的弧长；`frameAt(s)` 返回 T/N/B |
| `meridian/route.ts` | `buildRoute`、`resolveAnchor`、`Route` | `resolveAnchor` 会把手上锚点贴合到 `palmDorsalY` |
| `meridian/wushu.ts` | `STAGE_FLOW`、`flowAt` | 井→合 的宽度/速度/深度插值 |
| `time/tide.ts` | `tide(meridianId, hour)` | 子午流注潮位，M0 只做了单测，未接 UI |
| `rng/mulberry32.ts` | `mulberry32`、`hashSeed` | 同 seed 必须同地形 |

### 坐标约定（重要）

- 单位：**米**。手长约 0.18m，前臂约 0.255m。
- `hand.R`：原点在腕，`+x` 指指尖，`+y` 指手背，`+z` 指拇指侧（桡侧）。
- `forearm.R`：原点在肘，坐标轴同向（M0 直臂，无旋转）。
- 体表基面 `palmDorsalY(x,z)` 同时服务于身体网格与走廊地形，保证接缝不裂。
- 走廊参数域 `(s,t)`：`s` 沿经弧长，`t` 横向。因 `B = T × N` 在世界中指向 `-z`，**`t` 为负是拇指侧，为正是指掌中心方向**（`field.ts` 的 domain 注释有同样说明）。

### 测试

`test/meridian.test.ts`：schema、重复编码、5 个 authored 锚点贴合 <0.5mm、曲线长度/单调/连续性、潮位。

## 5. `packages/scene-gen` —— 生成层

```text
scene-gen/src/
├─ corridor/field.ts     # TerrainField：高度函数、水位、湿边、曲率、调色板
├─ corridor/build.ts     # 走廊网格 + 水面网格 + 属性（wet/concavity/edge）
├─ corridor/archetypes.ts # 六个原型的参数与随经混合
├─ qi/path.ts            # 谷底气路径 → 512×4 RGBA float 曲线纹理
├─ scene.ts              # M0_CODES 与 buildM0Scene 便捷入口
├─ protocol.ts           # 未来 Worker 的消息契约（当前未启用）
├─ noise.ts              # value noise / fbm / ridged
└─ index.ts
```

### `TerrainField` 负责什么

| 方法 | 产物 | 用途 |
| --- | --- | --- |
| `pointAt(s, t)` | 世界坐标 | 先投影回手背基面，再叠加位移 |
| `displacementAt(s, t)` | 位移（米） | 双脊、河谷、潭、山肩、细节 |
| `waterYAt(s)` | 水位 | 河道 → 潭面的平滑过渡 |
| `wettedSpan(s)` | 左右水线 `t` | 水面网格贴着河床生成，避免穿插锯齿 |
| `wetAt` / `concavityAt` | 0–1 属性 | 湿岩色、积墨 |
| `baseAt(x,z)` | 基面高度 | 身体与地形共用 |
| `palette` | 土/苔/岩/湿/雾/墨/水/光 | 传给 shader |

位移的组成（按代码顺序）：

```text
谷底高斯            -A · exp(-(t/σc)²)
两侧山脊            +0.64A · exp(-((t∓w)/σr)²)   w≈7.8mm
掌骨/鱼际山肩       +0.5–0.7mm 高斯
五输河道下切        -(0.35–1.05mm，随井→合) · exp(-(t/wr)²)
合谷汇水潭          -1.8mm 高斯（椭圆）
fbm / 脊噪声 / 皴纹  ±0.1–0.7mm
边缘衰减            × 横向/纵向 smoothstep，接回皮肤
```

峰值约 5.7mm，低于架构文档的 6mm 上限；`test/corridor.test.ts` 会守住这条线。

### `buildCorridor` 的产物

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `terrain` | `MeshData` | position/normal/uv/index，199×123 顶点 |
| `water.river` | `MeshData` | 每行按湿边生成的水面 |
| `water.pool` | `MeshData` | 合谷潭盘（M0 未渲染，保留给后续） |
| `wet` / `concavity` / `edge` | `Float32Array` | shader 属性 |
| `sValues` / `tValues` | `number[]` | 参数域，供调试与测试 |
| `bounds` / `hegu` | `Vec3` | 包围盒与谷底世界坐标 |
| `field` | `TerrainField` | 后续查询（水位、点采样） |

`DEFAULT_BUILD` 控制步长：`ds=0.5mm`，谷底 `dt=0.3mm`，外缘 `1.2mm`。

### 气路径

`buildQiPath(field)` 沿 `field.pointAt(s, 0)` 采样 512 个点，抬高 0.6mm，烘焙成一张 4 行纹理：

| 行 | 内容 |
| --- | --- |
| 0 | 世界坐标 |
| 1 | 法线（≈ +y） |
| 2 | 副法线（T × N） |
| 3 | 归一化 s |

它只依赖 TerrainField，因此可单测、可离线烘焙；渲染层拿到的是一张 DataTexture。

### 其它文件

- `scene.ts`：`M0_CODES = ['LI1','LI3','LI4','LI5','LI11']` 与 `buildM0Scene()`，给测试/脚本用；Web 端为了参数重建，拆成 `buildRoute` + `buildCorridor`。
- `protocol.ts`：`BuildRequest` / `BuildMessage` / `BuildPayload`，M1 迁 Worker 时直接实现；当前主线程调用 `buildCorridor`。
- `noise.ts`：确定性 2D 噪声，无第三方依赖。

## 6. `packages/render` —— 渲染层

```text
render/src/
├─ terrain/terrainMaterial.ts  # 地形 ShaderMaterial（颜色、法线扰动、积墨、雾）
├─ terrain/TerrainView.ts      # 数据 → BufferGeometry / Mesh
├─ water/waterMaterial.ts      # 水面 shader（fresnel、流动法线、高光）
├─ water/WaterView.ts          # 河道网格装配
├─ body/bodyBase.ts            # 程序化手掌 + 五指 + 前臂 + 上臂 + 颈/头
├─ body/BodyAnchors.ts         # 20 穴总览点 + 经线 + 穴码
├─ markers/MeridianMarkers.ts  # 穴位环 + 名称 Sprite
├─ mist/MistView.ts            # 谷口/潭面雾气 Sprite
├─ qi/QiView.ts                # 3000 个气粒子：曲线纹理 + 相位采样 + 潭心回旋
├─ press/PressView.ts          # 候气涟漪环（贴地形法线）
├─ camera/CameraRig.ts         # 观 / 游 / 驻 三种机位
└─ index.ts
```

| 模块 | 要点 |
| --- | --- |
| 地形材质 | 按坡度/苔藓/岩层混合；`aWet` 湿岩、`aConcavity` 积墨、`aEdge` 边缘化入皮肤；`uFogDensity`、`uWaterY`、`uSkin` |
| 水面材质 | 正弦波纹扰动法线、fresnel、太阳高光；`transparent + depthWrite:false`；边界来自湿边网格 |
| 身体基座 | 手掌用 `palmDorsalY` 生成；走廊范围用矩形遮罩 discard（`zc0/zc1`、`spanUlnar/spanRadial`）；半透明「体」层；颈/头为示意体块 |
| 20 穴 | `BodyAnchors` 把 20 个锚点连成经线；总览时显示，关键穴带穴码 |
| 标记 | 环与标签都贴到 `field.pointAt(stop.s, 0)`；`setLabelsVisible` 由场景开关控制 |
| 雾 | 6 个 Sprite，按时间漂移；相机进入 4.5cm 内自动隐藏 |
| 气粒子 | 沿谷底曲线纹理流动；3000 点、additive、depthTest；观/游/驻不同透明度，`qi` 图层可关 |
| 候气 | 长按 180ms 命中地形；气粒子的吸引/回旋、水面波纹、两圈贴地光环；移动 >5px 取消 |
| 相机 | `CameraRig` 持 OrbitControls；游模式用弧长乒乓 + 弹簧平滑；`getFocusS()` 供象卡定位 |

**约定**：render 不解析内容、不生成地形，只接收 `CorridorMeshData` / `Route` / `TerrainField`。

### `SceneHost` 的生命周期

```text
constructor
  ├─ buildRoute(meridian, M0_CODES)          // 曲线只算一次
  ├─ buildCorridor(route, params)            // 地形/水
  ├─ WebGLRenderer + Scene + 灯光 + FogExp2
  ├─ CameraRig(field, hegu, mode)
  ├─ createLayers()                          // terrain/water/body/markers/mist/qi
  ├─ ResizeObserver + requestAnimationFrame
  └─ window.__SCENE__ = this                 // 调试入口

loop
  ├─ 首屏：field 主线程 → CorridorService（缓存/Worker）→ 建图层 → onReady
  ├─ 总览：setOverview(true) → 相机拉远 → 隐藏地形/水/气 → 显示身体 + 20 穴
  ├─ 参数脏且静置 >120ms → rebuildTerrain()（field 主线程；网格 Worker/缓存）
  ├─ 异步结果回来 → swapCorridor()（旧画面保留到新数据 ready）
  ├─ rig.update(dt)
  ├─ 图层可见性（body 仅 observe；标签按开关；穴位环观/巡游；mist 近景隐藏）
  ├─ 长按 180ms → Raycaster 命中地形 → 候气强度 / 吸引点
  ├─ water.update / mist.update / qi.update / press.update / uTime
  └─ render → FPS 每 0.5s 回传 React

setParams → 标记脏 + 记时间；重建时只替换 terrain/water/mist/markers，身体与相机保留
setMode   → CameraRig 切机位
dispose   → 取消 RAF、断开 ResizeObserver、释放几何/材质/renderer
```

### URL 参数

`mode=observe|fly|dwell`、`archetype=auto|valley|stream|gorge|pool|well|pass`、`valley=`、`river=`、`relief=`、`fog=`、`body=1`、`qi=0`、`labels=1`、`ui=0`。
默认：observe、body 关、labels 关、雾 7。

### 状态归属

- React：模式、参数、图层、FPS、三角面、加载/错误。
- xstate：巡游的站点顺序与停留（`useActor`），不直接操作 three。
- three：相机、材质 uniform、几何、动画时间。
- 三者只通过 `SceneHost` 的方法与回调通信，不互相读内部状态。

## 10. 一次数据流：从 JSON 到像素

```text
content/*.json
  │ ① App.tsx import（Vite 构建期）
  ▼
parseMeridian() ── zod ──► Meridian
  │ ② findPoint(LI4) → 象卡文本
  ▼
buildRoute(meridian, M0_CODES)
  │ resolveAnchor：帧 + 局部坐标 → 世界坐标（手背点贴合基面）
  │ MeridianCurve：向心 Catmull-Rom → 0.5mm 重采样 → controlS
  ▼
Route { curve, stops, s0, s1 }
  │ ③
  ▼
buildCorridor(route, params)
  │ TerrainField.pointAt/displacementAt → 199×123 顶点
  │ 湿边扫描 → river 网格
  │ 计算 wet / concavity / edge
  ▼
CorridorMeshData
  │ ④
  ├─► createTerrainView  → BufferGeometry + ShaderMaterial
  ├─► createWaterView    → BufferGeometry + WaterMaterial
  ├─► createMarkerView   → 环 + Sprite
  └─► createMistView     → Sprite
  │ ⑤
  ▼
SceneHost.loop → CameraRig + 时间 uniform + renderer.render → Canvas
  │ ⑥ 滑块
  ▼
SceneHost.setParams → 120ms 防抖 → 重新 buildCorridor（route 不变）→ 替换图层
```

性能注记：一次 `buildCorridor` 约 60–100ms（M 系列 / Node 22）；渲染约 5 万三角面。

## 12. 约定

| 主题 | 约定 |
| --- | --- |
| 单位 | 米；位移在毫米级 |
| 颜色 | 内容里用 `#RRGGBB`；three `Color` 负责 sRGB→线性 |
| 随机 | 只用 `mulberry32`/`hashSeed`/`fbm2`，禁止 `Math.random()` |
| 确定性 | 同 seed 同参数必须逐字节一致（单测覆盖） |
| 占位锚点 | `anchorStatus: "placeholder"`；发布构建必须失败 |
| 文件命名 | 经脉 JSON 用英文 kebab-case；包内文件 PascalCase（组件/类）或 camelCase（工具） |
| 依赖 | core/scene-gen 不 import three；web 不写地形算法 |
| 单位测试 | 只测纯函数/纯数据；three 对象不单测，用截图回归 |
| 提交物 | `docs/screenshots/*.jpg` 属于文档，不忽略；`.tmp/`、`dist/`、`node_modules/` 忽略 |

## 13. 常见改动指南

### 新增/修改一个穴位

1. 在 `content/meridians/*.json` 填 `anchor.frame`、`local`、`normal`，把 `anchorStatus` 改为 `authored`。
2. 若点在现有手/前臂基座上，`resolveAnchor` 会自动贴合；跑 `pnpm content:validate` 看距离是否 <0.6mm。
3. 若要进入巡游路线，把编码加进 `packages/scene-gen/src/scene.ts` 的 `M0_CODES`（或未来从内容读）。
4. 补 `pnpm test`：锚点贴合、曲线单调。

### 新增一类地形特征（原型）

1. 在 `TerrainField.displacementAt` 里加分支，参数从 `options` 或 `content.image.params` 读。
2. 如需新颜色，扩展 `TerrainPalette` 与 `terrainMaterial.ts` 的 uniform。
3. 加单测（谷形/振幅/水面），再跑截图看是否破坏现有构图。

### 新增一条经脉

M0 里还有几处硬编码需要先泛化（M1 任务）：

- `apps/web/src/App.tsx` 固定 import 了 LI 的 JSON；
- `scene-gen` 的 `TerrainField` 固定取 `LI3/LI4/LI5`；
- `M0_CODES` 固定五穴。

步骤：内容文件 → 选段编码 → `buildRoute` → `buildCorridor`；同时把上面三处改成「当前经脉 + 当前段」的配置。

### 调参

优先用面板/URL 参数；确认后写回 `DEFAULT_TERRAIN`（`field.ts`）、`DEFAULT_BUILD`（`build.ts`）或 `CameraRig` 的机位常量。

### 调焦点窗口

- `packages/scene-gen/src/corridor/window.ts`：`planCorridorWindow` / `WindowTracker`；
- `packages/scene-gen/src/corridor/tiles.ts`：`TileManager` LRU/预热；
- 半宽 5cm、5mm 吸附、12mm 缓冲；相邻窗口预取；
- `SceneHost.loadInitial/rebuildWindow`：窗口 field + Worker/缓存；
- 远景：`packages/render/src/markers/ArmLine.ts`。

### 调经段

- `TerrainField` 的 `segment`：`surface: 'hand' | 'forearm'`、`s0/s1`、`focusS`、`autoS`、`tMin/tMax`；
- `SceneHost.SEGMENT_TOUR` 与 `SEGMENT_CODES`：经段的站点与路线；
- `CameraRig.applyMode`：前臂的观/驻偏移；
- URL：`?segment=forearm`。

### 调二十穴

- 锚点数据：`content/meridians/hand-yangming-large-intestine.json`；
- 帧：`packages/core/src/anatomy/hand.ts` 的 `FRAMES`；
- 总览相机：`CameraRig.applyOverview`；
- 雾：`SceneHost.setOverview` 里总览 0.45 / 平时 `params.fogDensity`；
- 入口：图层「全身」、键盘 `4`、`?overview=1`。

### 调墨洗

- 材质：`packages/render/src/terrain/terrainMaterial.ts` 的 `rim / hatch / paper` 项；
- 开关：`TerrainView.setInk`，面板「图层 → 墨」；
- 墨量：`uInkBoost`（轮廓/皴擦）与 `uInkStrength`（积墨）；
- 纸纹：`hash21(gl_FragCoord.xy * 0.73) * 0.03`，只作用于地形。

### 调原型

- 参数：`packages/scene-gen/src/corridor/archetypes.ts` 的 `ARCHETYPES`；
- 随经权重：`autoParamsAt` 的 band（默认 22mm）与三站弧长；
- 水带宽度：`buildRiver` 里 `poolSigmaT × 0.6` 的封顶；
- 调色板：`field.ts` 的 `ARCHETYPE_PALETTES`；
- 新增原型时要同步 `ARCHETYPE_OPTIONS`、`ARCHETYPE_PALETTES` 与单测。

### 调巡游

- 站点顺序：`apps/web/src/journey/tourMachine.ts` 的 `TOUR_STOPS`；
- 停留时长：`HOLD_MS`（默认 3.6s）；
- 平移速度：`CameraRig.updateFly` 里的 `0.016` m/s；
- 端头留边：`SceneHost.goToStop` 的 +4mm / −8mm 偏移；改站点时要一起看回望方向（`tourLookDir`）。

### 调气粒子与候气

- 路径形状：`buildQiPath` 的 `lift` 与采样数；
- 密度/大小/速度：`QiView` 的 `count`、`uSize`、`uSpeed`；
- 回旋强度：顶点着色器的 `pool` 高斯与 `swirl` 系数；
- 候气：`SceneHost` 的长按阈值（180ms / 5px）、吸引半径（12mm）与位移（2.2mm）、`PressView` 的环半径与透明度；
- 不要改成 CPU 逐帧积分，否则回放与性能都会失控。

### 迁 Worker

`packages/scene-gen/src/protocol.ts` 已定义消息；把 `buildCorridor` 放进 `apps/web/src/workers/scene-gen.worker.ts`，主线程只保留 `buildRoute` 与 three 装配；结果用 transferable 回传 `positions/normals/indices/uvs` 等 TypedArray。
