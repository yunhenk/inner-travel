# 游脉山河 · 全身经脉技术方案

> 目标：不是把 20 个穴做成 20 个场景，而是让**整张体表**成为一张连续的地形，
> 十二条正经、奇经八脉都能在同一个人身上走通。

- 状态：技术方案（2026-11-03）
- 范围：从当前「手阳明大肠经手背/前臂两段」扩到全身
- 结论先行：**必须做 LOD，而且从第一版就要按 tile 设计**；但 LOD 不是第一步，
  第一步是把「世界 y 高度场」换成「体表局部标架 + 曲面片」。

---

## 1. 当前方案为什么走不通

| 问题 | 根因 |
| --- | --- |
| 手背与前臂分段 | 手背法线朝上（y），前臂桡侧法线朝侧（z）；两套高度场无法在同一 y-up 世界拼接 |
| 腕部峭壁 | 在 y-up 高度场里强行 blend 两种法线，腕口会出现 90° 垂直墙 |
| 切前臂很久 | 点击时销毁/重建整个 `SceneHost`：WebGL 上下文、shader、所有图层、Worker + 缓存 miss |
| 多经脉不可扩展 | 每条经一套地形/一个场景，12 条经就是 12 个世界 |

根因不是参数，是**几何表示**：经络贴在体表，体表不是一张水平地面。

---

## 2. 核心抽象

### 2.1 BodySurface

全身共享的体表：

```ts
interface BodySurface {
  /** 世界点 → 体表最近点/UV/法线 */
  project(point: Vec3): SurfaceSample;
  /** 曲面上的点 + 局部标架 */
  frameAt(uv: Vec2): SurfaceFrame;
  /** 两条体表点之间的测地距离（近似） */
  geodesic(a: Vec2, b: Vec2): number;
}

interface SurfaceFrame {
  position: Vec3;  // 体表点
  normal: Vec3;    // 外法线
  tangent: Vec3;   // 沿经脉
  lateral: Vec3;   // T × N
}
```

实现优先级：

1. 程序化身体（当前 M0 基座）→ 分肢体 chart（手背、前臂、上臂、躯干、头颈）；
2. 带骨骼 GLB → 骨骼空间 + 蒙皮后的体表采样；
3. 长期：单一 body mesh + BVH/UV chart，所有经脉共享。

### 2.2 MeridianPath

穴位不再只存世界坐标，而是存**体表参数坐标**：

```ts
interface Anchor {
  surface: 'hand.R' | 'forearm.R' | 'upperarm.R' | ...;
  uv: [number, number];      // 或 chart 内参数
  normal: [number, number, number];
  bone?: string;             // GLB 后用于蒙皮
}
```

- 20 穴/经 × 12 经 = 240 个锚点；
- 路径在体表上插值，而不是在 3D 空间里拉一条曲线；
- 曲线、地形、相机、气、水都用同一套 `SurfaceFrame`。

### 2.3 SurfaceTile

走廊不再是一个全局 heightfield，而是**体表上的曲面片**：

```text
tile = 2cm 沿经 × 走廊宽度
顶点 = surface.frameAt(s,t).position
       + normal * displacement(s,t)
水面 = frame.position + normal * waterOffset(s,t)
```

- 位移沿局部法线，不沿世界 y；
- 水、气、相机也用局部法线；
- 腕部只是法线平滑旋转，不会出现峭壁；
- 每条经由一串 tile 组成，tile 可以独立 LOD、裁剪、缓存、流式加载。

## 3. 多经脉如何连在一起

### 3.1 共享体表，而不是共享世界

- 所有经脉挂在同一个 `BodySurface` 上；
- 穴位是体表上的节点，经脉是节点之间的测地路径；
- 交汇穴（如合谷、曲池）是图节点，不是两个独立场景的边界。

### 3.2 MeridianGraph

```text
节点：穴位（体表 UV + 法线 + 骨/区段）
边：经脉段（同一经相邻穴，或络脉/经别连接）
```

- 十二正经 + 奇经八脉共用一张图；
- 巡游是图上的路径搜索，不是硬编码的站点数组；
- 跨经换乘在交汇穴完成，相机沿体表过渡。

### 3.3 地形重叠/接缝

多条经在穴位附近会靠得很近，建议：

- **tile 化**：每条经的走廊是独立 tile，边缘做 skirt/共享边；
- 交汇穴用一个**共享的节点 tile**，把几条经的位移做加权混合；
- 水/气按经归属，避免同一水面重复渲染；
- 远期若做统一位移图集，可把多条经烘到同一张体表 displacement atlas。

## 4. LOD 设计：需要，而且必须从第一版留接口

### 4.1 三档 LOD

| 档位 | 触发 | 沿经步长 | 横向步长 | 三角形/段 | 水/气 | 标签 |
| --- | --- | --- | --- | --- | --- | --- |
| L0 近景 | 焦点 0–5cm | 0.4–0.5mm | 0.3mm | 40–80k | 完整水面 + 3000 气粒 | 当前站 |
| L1 中景 | 5–20cm | 1.5mm | 1mm | 10–20k | 简化水面 + 800 气粒 | 关键穴 |
| L2 远景/全身 | >20cm | 不生成走廊 | — | 0（或 2k 示意带） | 无 | 穴位点/经线 |

- 判据：**屏幕空间误差**优先（投影后 <1px），辅以测地距离；
- 用 10% 滞回，避免边界抖动；
- LOD 切换用 skirt/交叉淡入，不能出现裂缝；
- 全身视角只保留当前经的 L2 线 + 穴位点，不渲染 12 条经的高模。

### 4.2 Tile 与流式

- tile 尺寸：沿经 2cm，横向整条走廊；
- 每 tile 三档 LOD，Worker 生成，IndexedDB 缓存；
- 只保留焦点附近 8–12 个高模 tile，其余降级/驱逐；
- tile 的边界顶点共享，法线/水位在边界插值，避免接缝；
- 这样点击/换经不再重建 `SceneHost`，只是 tile 换入换出。

### 4.3 Body LOD

- 身体本身也需要 LOD：近景 60–80k，远景 15–30k，或单套中模 + normal map；
- GLB 后做 3 档或自动减面；
- 远景身体只保留轮廓和经脉线，避免和走廊抢三角形。

### 4.4 其他 LOD

- **气**：L0 3000 点 → L1 800 → L2 关闭；
- **水**：L0 网格 → L1 简化带 → L2 只保留线；
- **标签**：L0 全标签 → L1 关键穴 → L2 点/悬停；
- **后处理**：DOF/墨线按 DPR/帧率降级；
- **多经**：当前经 L0/L1，邻近经 L1，其余 L2 线。

### 4.5 性能预算

- 桌面 60fps：<150k 三角形、<80 draw call、<40MB tile 缓存；
- 移动 30fps：<60k 三角形、半分辨率、气粒 ≤800；
- 全身视角：<30k 三角形（身体 + 经线 + 穴位点）。

## 5. 相机与交互

- **局部 up**：相机 `up` = 焦点处体表法线；
- 全身缩放时把 `up` 平滑回世界 up，避免整屏翻滚；
- 巡游沿 MeridianGraph 的边，站点停留；跨经在交汇穴换乘；
- 近景（<5cm）只看当前 tile；中景看一段；远景看全身经线；
- 减少运动：`prefers-reduced-motion` 下降低相机滚动与 LOD 交叉淡入。

## 6. 数据与资产

- 20 穴/经 × 12 经 = 240 锚点，全部用体表 UV/骨坐标；
- 内容 schema 增加 `surface`、`uv`、`bone`，旧 `local` 保留为 fallback；
- 身体资产：
  - 短期：程序化身体 + 分肢体 chart；
  - 中期：带骨骼 GLB（手 → 前臂 → 上臂 → 躯干 → 头颈）；
  - 长期：单一 body mesh + BVH + 皮肤 UV；
- 经脉曲线在体表上做测地插值，避免穿透/悬空。

## 7. 实施顺序

### Phase 0：冻结现状

- 当前分段版保留为 fallback；
- 不再给分段加功能。

### Phase 1：体表局部标架 + 单条连续经

- `BodySurface` 接口（程序化 chart）；
- LI3–LI11 一条 route、一串 tile；
- 位移/水/气/相机全部走局部法线；
- 删除经段切换，单场景、单次加载；
- 目标：腕部无峭壁，巡游 9 站。

### Phase 2：Tile/LOD 管理器

- 2cm tile、三档 LOD、Worker + IndexedDB；
- 焦点 L0、邻近 L1、远处 L2；
- 相机局部 up + 全身 up 混合；
- 目标：换经/换段不重建场景。

### Phase 3：多经图

- MeridianGraph、交汇穴、共享节点 tile；
- 先接 2–3 条经（如 LI + LU + PC），验证交汇与换乘；
- 目标：同一身体上多条经连续。

### Phase 4：全身与 GLB

- 12 经 + 8 脉；
- GLB 骨骼/蒙皮，锚点跟骨；
- 全身 LOD 与性能收口。

### Phase 5：后处理

- DOF/墨线在 tile/标签 overlay 之后；
- 按性能降级。

---

## 8. 关键取舍

- **不做全局 heightfield**：y-up 高度场无法表达手背/前臂/躯干的法线变化；
- **不做 12 个独立场景**：必须是同一 BodySurface + 同一场景；
- **LOD 不是优化阶段才做**：tile 边界、接缝、缓存、相机都要从第一版按 LOD 设计；
- **先做一条连续经，再做多经**：先证明腕部/肘部/肩部的局部标架，再扩图；
- **GLB 可以后置**：程序化 chart 先把 surface 抽象跑通，GLB 只替换采样源。

## 9. 与当前代码的映射

| 现在 | 目标 |
| --- | --- |
| `TerrainField.pointAt` 世界 y | `SurfaceFrame.position + normal * displacement` |
| `TerrainSegment` 手背/前臂 | `SurfaceTile` 按体表 chart 切分 |
| `SEGMENT_TOUR` 两段 | `MeridianGraph` 路径 |
| `SceneHost` 切换时重建 | 单 SceneHost + TileManager |
| `buildCorridor` 一次全量 | tile 按需生成 + LOD 缓存 |
| `Point.anchor.local` | `Point.anchor.surface + uv/bone` |

## 10. 一句话回答

**需要 LOD，而且要从 tile 化开始设计；但第一步不是 LOD，而是把地形从「世界高度场」改成「体表局部标架曲面片」。** 只有这样，手、前臂、上臂、躯干、头颈才能在同一个人身上连续，十二条经也才能共享同一张体表。
